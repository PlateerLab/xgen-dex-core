## 9개 지적 사항의 반영 정도

1. **검증된 것만 done: 기존 수정 + 추가 보완, 일부 실제 앱 검증.** 시작점에 업로드 실패·팝업 되묻기와 complete 집계 수정이 이미 있었다. 이번에는 서식 편집기·팝업 후 입력도 읽어 확인하고, 글의 부호·구두점 차이를 무시하지 않도록 했다. 체크·펼침 상태를 읽지 못하면 완료에서 제외한다. 일반 입력, 서식 입력, 잘린 입력, 체크 반복은 실제 화면을 확인했다. 최신 코드의 실제 파일 업로드 전체 경로는 재검증하지 않았다.

2. **page_id: 기존 필수화 + 범위/원격 차단 보완.** 입력·결과의 page_id 필수화는 이미 있었다. BrowserFill의 다른 기기 요청을 거부하고, 실행 중 허용된 폼과 그 자식 팝업 밖의 명령을 차단했다. 닫힌 탭도 원래 page_id를 결과에 남긴다. 동일 제목·URL A → B → A는 실제 채팅 통과. 다른 기기 차단은 내부 테스트로 확인했다.

3. **줄 수·부분 결과: 새로 보완.** 50줄 상한, 줄별 예외 격리, 취소·시한·탭 닫힘 시 완료 결과 보존, 업로드 승인창 대기 취소를 추가했다. 서버에는 완료 줄을 반복하지 말고 failed/skipped를 현재 값부터 확인하도록 전달한다. Electron 실행 스모크에서 가짜 실행기와 단축 시한으로 검증했다. **실제 110초 만료, 실제 업로드 중 취소, 실제 탭 닫힘의 사용자 흐름까지 확인한 것은 아니다.** 이미 전송된 브라우저 명령 하나가 늦게 끝날 가능성은 남아 있어 진행 중인 줄을 안전하게 재실행 가능한 것으로 표시하지 않는다.

4. **저장·등록·승인요청 차단: 이미 코드에 반영.** 시작점 `09b3531`에 실제 DOM 이벤트 차단과 명시적 승인 후 120초·1회 허용이 있었다. 조회·로그인·화면 이동과 구분한다. Electron 로컬 시험 폼에서 입력, 제출, 키 입력, 자식 프레임, 승인 소모·만료·취소를 재검증했다. 자연어 값 `삭제하지 않고 보관합니다`는 실제 앱의 서식 칸에 빠르게 입력됐다. 실제 BO 저장은 시험하지 않았다. 의미를 노출하지 않는 사용자 정의 위젯까지 완전히 식별한다는 보장은 아니다.
